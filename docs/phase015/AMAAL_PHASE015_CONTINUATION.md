# AMAAL — PHASE 015 CONTINUATION

## Purpose

This release is a continuation of the Master Improvement Blueprint. It was made after re-inspecting the Phase 014 archive rather than assuming the previous completion claims were sufficient.

## Newly completed in Phase 015

### Customer account and service
- Added working server-side customer access-token issuance and validation used by the storefront account flows.
- Added customer sign-out that revokes the current storefront token.
- Added persistent customer order-detail retrieval with order-line IDs, variants and products.
- Added saved-address removal and update support in the public account layer.
- Added customer notification read and mark-all-read actions.
- Added customer communication preferences with transactional and marketing preferences separated.
- Improved My Amaal to expose unread updates, preferences and sign-out.
- Improved order history to use database history when a customer account is available rather than only browser-local orders.
- Improved returns so customers can select individual order lines and quantities instead of silently returning the first order line.

### Search and discovery
- Search results now record search events from the public search page.
- General comparison now combines database catalogue products with the curated phone, TV, computer, audio, tablet, accessory and appliance catalogues.
- Comparison can show available category-specific specification fields without inventing missing values.
- Related-product API now uses explicit Business Console relationships first and a controlled same-category/same-brand fallback when no relationship has been curated.
- Added customer-facing buying guides for phones, TVs, laptops, refrigerators, washing machines and audio.
- Added buying guides to primary navigation.

### Commerce UX
- Added a real client-side shopping-bag drawer with quantity controls, removal and checkout links.
- Added an optional customer-controlled Save this bag action using the abandoned-cart foundation.
- Product cards and database product detail pages can now display an attached public catalogue image when an approved image exists; placeholders remain when there is no approved image.
- Added public customer support submission connected directly to the existing Business Console support-case/customer records.
- Added a dedicated public repairs/service-history page.
- Expanded the Services page into direct delivery, returns, warranty, repairs, support and FAQ entry points.

### Reviews and trust
- Customer-token identity can now be used for review/question submissions.
- Delivered purchases can be automatically recognised for a signed-in customer review when the product belongs to the delivered order.
- Duplicate review submission for the same delivered order/product is blocked.
- Existing Business Console moderation remains the approval authority.

### Notifications
- Added notification source keys for order/delivery status notifications to prevent repeated identical status notifications from being generated by repeated admin actions.
- Added account notification controls without creating external messaging claims.

### SEO and public discovery
- Added public sitemap generation.
- Added robots metadata generation.
- Added buying-guide routes to the public site structure.

## Important correction found during re-inspection

Phase 014 referenced customer-token helper functions from the checkout/account flow without defining them in `server.js`. Phase 015 defines and validates those helpers. This was a real runtime defect that source syntax checks alone could not detect.

## Why these remain deferred

Amaal is a new business. Payment and external communications should not be simulated. They require real provider credentials, commercial agreements, compliance configuration and production webhook endpoints. The storefront therefore presents the accepted payment methods without claiming money has been collected.

## Architecture rules preserved

- Business Console remains the single product-management surface.
- Public website does not expose product CRUD.
- No database reset, TRUNCATE or destructive migration was introduced.
- All new SQL is additive/idempotent.
- Server remains authoritative for price, inventory, reservations, orders and payment state.
- Audio remains under Entertainment → Audio.
- Business laptops remain excluded.
- Manufacturer website links remain excluded from the public shopping experience.
- Product specifications, availability, reviews and prices are not invented.
- Approved public media can flow from Business Console media records into product imagery.
- Historical business records are preserved.

## Phase 015 build-blocker repair — 2026-09-02

### Real defect fixed
The Vercel production build reached the TypeScript stage and failed in `apps/public-web/app/compare/page.tsx`. The `all` catalogue expression accidentally created nested arrays because several catalogue `.map()` calls were inserted as array members rather than flattened elements. TypeScript therefore inferred `Row | Row[]`, which broke the `rows`, `find`, and comparison-table rendering types.

### Repair
The comparison catalogue aggregation was rewritten into explicitly typed intermediate arrays (`catalogue`, `phones`, `computers`, `tvs`, `audio`, `tablets`, `accessories`, `appliances`) and one final flattened `Row[]` return. TV size handling was also made defensive for catalogue entries where `sizes` is not an array.
